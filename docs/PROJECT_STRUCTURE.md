# 项目结构与整理基线

本文记录当前结构和后续整理的预留位置，不改变程序启动方式。

## 当前结构

- 根目录的 `app.py`、`*_engine.py`、`*_workflow.py` 等是目前实际使用的后端代码；启动脚本和配置文件仍在根目录。
- `frontend/` 是目前使用的前端源码；组件、样式和前端测试分别位于 `components/`、`styles/` 和 `tests/`；`static/` 是现有静态页面资源。实际入口以现有启动脚本和配置为准。
- `tests/` 存放后端测试；`docs/` 存放项目说明；`.agents/skills/` 存放项目 Skill。
- `datasets/`、`runs/` 和 `.stata-tmp/` 保存运行数据、结果或临时文件；虚拟环境、依赖目录和缓存同样属于本地运行环境。整理源码时不应把这些目录当作无价值文件删除。
- `web-build/`、`web-build-next/` 和类似目录是前端构建或启动过程中可能使用的产物，不是需要迁移的源码。

## 预留位置

前端界面组件已迁入 frontend/components；后端目录和 frontend/app 目前仍是预留位置。目录含 `.gitkeep` 仅用于版本控制，不是 Python 模块入口，也不会自动加载。

```text
backend/
  api/       # 后续拟放接口相关代码
  agent/     # 后续拟放 Agent 编排相关代码
  analysis/  # 后续拟放分析工具
  data/      # 后续拟放数据处理代码
  stata/     # 后续拟放 Stata 交互代码
frontend/
  app/       # 后续拟放前端入口和应用状态
  components/# 界面组件
  styles/    # 页面样式
  tests/     # 前端测试
```

除 frontend/components 的组件外，这些仍是候选位置，并不表示其他文件已迁移。具体拆分应先核对调用关系，并在每个阶段确认后进行；不能因为目录名称就移动代码。涉及移动或重命名时使用 `git mv`，同步检查启动脚本、导入、测试和构建配置。

## 整理基线

`structure-baseline.tsv` 记录建立本阶段结构前已暂存文件的路径、Git 索引 blob 标识及工作区文件的 SHA-256。换行转换可能使 Git blob 与工作区字节不同，因此两列分别表示不同的对象。此后有意追加的 `.gitignore` 忽略规则会使其工作区哈希与基线不同。

基线只供核对文件内容和路径，不包含文件备份，也不能代替提交历史。目前本地仓库未创建提交，不能把这份清单说成 Git 提交或完整的重命名历史。不要将数据、日志、密钥或本地环境目录加入版本控制。

## 启动与运行数据

继续使用现有启动入口和端口，不必为这些空目录重启服务。使用启动、重启或清理脚本前应阅读其实际行为：部分入口会清理上传数据和历史产物，需先保存需要保留的内容。不要为了整理目录停止运行中的 Stata 会话或删除已有数据。

## 已完成的组件整理

- `frontend/components/`：布局、聊天消息、数据工作区、ETL 和分析结果等界面组件；入口及相关测试已更新导入路径。
- 本次移动不更改组件逻辑，现有前端入口和后台服务保持原位。

## 测试与后端边界

前端可运行 `npm test`；统计表测试已明确指定浏览器模拟环境。后端测试位于 `tests/`；包含真实 Stata 调用的测试默认跳过。后端模块仍位于根目录，因为启动入口和测试直接依赖其现有导入路径，未经兼容验证不要移动。完整运行和交接说明见 `CONTRIBUTING.md`。
