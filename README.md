# EconAgent Studio · 本地 Stata 研究工作台

本项目采用 React 前端和 FastAPI 后端，通过本地 MCP 服务调用 Stata。可以上传数据，在网页查看真实变量及前 10 行，围绕当前数据与模型对话，并查看 Stata 生成的代码、输出和文件。

## 启动

准备 Stata 17+（需可用许可）、Python 3.11+、Node.js、`uv` 和所选模型服务商的 API 密钥。API 使用和计费由各服务商决定。首次安装需要联网：

```powershell
cd D:\Mystata
uv venv .venv
uv pip install --python .venv\Scripts\python.exe -r requirements.txt
npm install
npm run build
.\.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8766
```

打开 http://127.0.0.1:8766，在“模型设置”中选择服务商，填写接口地址、对应 API 密钥和可用的模型名称。DeepSeek 默认地址为 `https://api.deepseek.com`，模型示例为 `deepseek-flash`；OpenAI、阿里云百炼、硅基流动和自定义 OpenAI 兼容 Chat Completions 接口也可选择。具体模型必须支持工具调用，且需要对应账户具备权限。百炼密钥的地域需与地址一致；其预填地址为中国区旧域名，新工作区可在控制台查看专属地址。原生 Anthropic / Gemini 接口不在本次兼容范围。

双击项目里的“Stata研究助手”快捷方式会启动或打开本机 8766 端口的服务。

已有 `.venv` 和构建产物时，直接运行最后一行即可。模型设置支持将 DeepSeek 官方接口密钥和模型名保存到当前 Windows 用户的 `DEEPSEEK_API_KEY` 和 `DEEPSEEK_MODEL` 环境变量；不勾选时密钥仅保存在服务内存。环境变量不是加密存储，当前用户的其他程序可能读取。OpenAI 可通过 `OPENAI_API_KEY` 和 `OPENAI_MODEL` 环境变量配置。切换服务商或接口地址必须重新填写密钥，避免向错误的地址发送原密钥；切换模型也会清空模型对话上下文。

Stata 默认位置为 `D:\stata\StataMP-64.exe`，可通过 `STATA_PATH` 修改。MCP 服务在首次分析时启动，首次运行可能需要下载依赖。

## 使用

1. 在原始文件池中拖拽或选择多个 `.dta`、UTF-8 `.csv` 或 `.xlsx` 文件，单文件上限 60 MB，Excel 使用第一张表。上传不会覆盖已有主分析集。
2. 可直接挂载单个文件，或勾选至少两个文件，进入“数据整合（ETL）”，核对合并模式、字段映射、类型与主键，然后确认执行。仅有真实 Stata 执行成功后才更新主分析集。
3. 在中间输入问题，右侧查看执行的 Do-file、Stata 输出及产生的文件。三栏分隔线可以拖动，键盘聚焦后可用方向键调整。切换主分析集会重置模型上下文。
4. 每次通过快捷方式重新启动后台前，会清空项目内 `datasets/`、`runs/` 和 `.stata-tmp/` 中的上传数据及历史产物，包括 Do-file、日志和结果；不会删除项目外的原始文件。需要保留的内容请在重启前下载或复制到项目外。重新打开已运行的后台不会自动清理，可使用页面右上角“清空数据”按钮随时清理。停止服务后 Stata 内存与网页密钥不会恢复。详细设计、合并语义与测试方法见 `docs/frontend-etl.md`。

需要输出表格或图表时，在对话中明确说明格式与内容。只有实际运行或生成的结果才会显示；不要将模型的解释直接视为已经过验证的研究结论。

## 边界

- 仅用于可信的本机单用户环境，务必绑定 `127.0.0.1`；当前没有登录、多用户隔离或 Stata 执行沙箱。Stata 代码以当前用户权限运行，建议使用数据副本。
- 原始文件保存在本机，但任务内容、变量信息和 Stata 工具输出会发送给选定的模型服务商。请勿提交不适合发送的敏感信息。
- 状态显示仅检查配置和文件是否存在，不代表密钥、模型或 Stata 许可已经验证。
- 一次执行一个任务；暂不支持流式进度、取消、跨重启恢复对话、文件管理或自动选择 Excel 工作表。单次任务最多 12 轮工具调用。
- 当前前端显示真实日志和原始数据，不会凭空生成回归表或诊断图；需要时让助手运行相应代码，结果文件可在“产物”中下载。
- `mcp-stata` 固定为 3.3.0 并使用 `mcp<2`；`mcp_launcher.py` 为当前 Windows 环境中的 Stata 输出提供兼容处理。正式部署前应审核和固定全部依赖。

## Stata 数据准备 Skill

项目级技能位于 `.agents/skills/stata-data-workflow/SKILL.md`。网页对话后台会在每次请求时读取该文件；当问题涉及数据检查、清洗或合并时，模型按该流程使用现有的 Stata 执行工具。原始文件池会提供文件名、项目路径、格式和规模等简要索引，不自动发送原始数据行；模型执行 Stata 检查后的输出仍可能发送给模型服务商。

上传并勾选数据后，可在对话中描述主表、目标观测单位、主键、样本规则和所需产物，例如“按公司代码和年份检查两张表，再说明清洗与合并方案”。用户已明确的规则无需重复确认；涉及无法从数据确定的统计口径时，助手应先提出具体问题。

Skill 是模型工作指引，不是新的 MCP 工具或强制执行规则。现有工具可用性取决于后台与 Stata/MCP 的实际连接；用户界面提供的 ETL 校验仍独立运行。真实代码和日志需查看执行输出；无法运行的步骤不能视为已完成。

## 字段检查工具

研究对话中的 `profile_columns` 对原始文件只读，按页返回字段目录，并可检查用户或模型指定的证券代码、年份和地区字段的格式。候选字段用途来自名称线索，须结合数据说明核实；名称与类型是源文件解析结果，Stata 实际导入后的名称和类型需以 Stata 为准。

工具不统计缺失值，不删除或更改数据。默认不检查重复；仅当用户明确要求并指出字段组合后才对全量原始字段值检查重复。重复样例只出现在本地执行输出，不发送给模型，模型仅收到汇总数量。检查格式时文件由本地 pandas 读取，CSV 按字符串读取、Excel 读取第一张表；检查不更改 Stata 当前数据。字段太多时按页返回。

例如：先勾选文件并输入“检查所选文件的字段和证券代码、年份格式”。只有需要重复检查时，再输入“检查 `id` 和 `year` 组合是否重复”。合并预检与实际合并是独立流程，不由此工具执行。

启动时自动清空项目内上传数据、结果和脚本；前端“清空数据”会在确认后立即执行同样的清理，卸载当前主分析集并清除执行记录，保留聊天显示和模型密钥。直接通过 uvicorn 命令启动不经过快捷方式的启动清理流程；仍可使用前端按钮。

在文件池勾选文件后，可点击“检查字段格式”，或在对话中输入“检查全部字段和格式”。纯字段清单不调用模型、不检查缺失或重复：.dta 直接读取文件头；CSV/Excel 用临时 Stata frame 按现有导入规则检查，结束后恢复原 frame。结果展示记录数、字段、存储类型、显示格式和标签。单纯字段清单无需 API 密钥。

研究对话栏的“清空对话”按钮会清除当前工作台显示的消息并重置模型对话上下文，不清除主分析集、原始文件、执行记录或运行目录中的日志和任务文件。

Do-file 面板优先显示可读版本，可切换至实际执行代码并下载；数据整合另生成 `etl-readable.do`，回归、绘图等通过 `run_stata` 执行的步骤各自生成对应可读文件。可读版源文件路径对应本机文件，换电脑时需修改；一般分析步骤可能依赖之前的 Stata 内存数据或估计结果。可读版不在每次任务时自动重新运行，失败步骤会标记失败。原始执行脚本与运行记录继续保留，旧合并任务在方案和数据仍存在时可生成可读版。

“数据调整”中的连续变量缩尾使用 Stata `winsor2`。每次自行指定变量、上下分位点与生成新变量或覆盖的方式；生成新变量时默认后缀 `_w` 可修改。也可在对话中说“对 ROE 和 Pay 上下各 1% 缩尾，生成新变量”。工具在当前主分析集的副本上操作，成功后挂载新结果并保存可读 do 文件；id、year 和仅含 0/1 的字段不会作为连续变量缩尾。Stata 必须能找到 `winsor2`；如未安装需先安装。为避免整数存储舍入分位点，新结果变量或覆盖变量使用 double 类型；生成新变量时源变量类型保持不变。

完成字段检查后，选中多个文件并向 Agent 提出明确的合并请求，例如“以 id 和 year 为键合并并挂载”，系统会先预检，成功后自动合并并挂载主分析集。要求“只预检，不要执行”时仅展示方案。默认 1:1，仅保留匹配行，再删除任一保留字段缺失的行；证券代码标准化为 `id`（long），年份标准化为 `year`（float），其他字段默认维持原类型，企业名称默认不保留。字段含义或年份口径不明确时需补充说明。所选键不唯一时会中止，不会自动去重。数据整合页面仍可手动调整方案。

## 第二版：研究上下文

第二版调整了上文提到的启动清理行为：通过普通快捷方式重新启动时保留上传数据和历史产物；需要删除时使用页面的“清空数据”。研究变量、数据集文件标识和成功的结构化分析结果保存在本地 `.econagent/`，不包含模型密钥或数据预览行。重启时仅在数据文件仍存在且校验值一致时尝试重新挂载；未保存的 Stata 内存修改、估计状态和聊天历史不会自动恢复。此功能启用以前的会话需要重新挂载数据并确认变量。

## 合并中的字段与年份范围

对话式合并允许 Agent 只指定关键字段和需要明确对齐的字段，程序会独立保留其他未映射字段，默认排除常见企业名称字段，并在合并记录中列出自动补齐和改名；不会仅凭名称把不同文件中的未映射字段认定为同义。证券代码和年份等关键候选字段仍须明确映射。

用户指定年份范围后，预检和正式合并使用相同的范围和包含端点规则，年份缺失和范围外记录会剔除；可读 do 文件记录实际筛选命令。数据整合页面也可设置年份字段及起止年份，修改方案后需重新预检。未指定范围时不自动筛选。

## DTA 删列与回滚

在对话中明确指定主分析集或文件池中的一个 DTA 文件，以及要删除的字段，例如“删除 ROE.dta 的 name 字段”或“删除主分析集的 name 字段”。工具先保存备份、检查结果，再直接替换工作台内的目标文件；上传前电脑其他位置的原始文件不会被修改。可说“回滚 ROE.dta 上一次删列”，也可点击文件池相应文件的“回滚”。每次只对一个文件操作。

回滚针对本工具记录的最近一次删列；如果目标文件之后被其他操作更改，系统拒绝覆盖。主分析集若有未保存的 Stata 内存修改，需先保存并重新挂载。备份位于项目 runs/field-undo/，使用“清空数据”会将备份一起删除；清空后无法通过此功能回滚。
# 多文件字段操作补充

对话中可以分别指定多个工作台 DTA 文件的删列或仅保留字段，例如“删除 Y 的省份，仅保留 X 的 stkcd 和 year”。系统先检查所有操作，然后逐个执行并分别备份；运行中途发生异常时会报告已经完成的文件，各文件可分别回滚。此前关于每次只能操作一个文件的说明由此补充替代。文件名简称必须能唯一对应工作台文件；字段及其归属不明确时需要补充说明。该功能只修改工作台副本或主分析集，不修改上传前的外部文件。
